# adsum-mobile

Part of the ADSUM platform (membership, QR check-in and attendance).
Subgroup: `applications`.

## Role

Android and iOS shell (Capacitor) wrapping the member application. Priority
delivery. The shell bundles the production build of `adsum-web-membre`, so the
mobile app ships the exact same UI, design system, onboarding, authentication
and business logic as the web member app: parity is guaranteed by construction,
not re-implemented.

## Stack

React 18, Vite, TypeScript (from `adsum-web-membre`), Capacitor 6 for the native
Android/iOS container.

## Why Capacitor (and not Expo/React Native)

The member experience is an existing React + Vite web app. Capacitor wraps that
build in a real native Android project (Gradle, `AndroidManifest.xml`, installable
APK/AAB) without rewriting the UI, and gives access to native plugins (status
bar, app lifecycle, and later camera for the controller QR scan). Expo Go and the
React Native testing routes do not apply here because the codebase is not React
Native. The correct testing route for this stack is therefore the Android Studio
emulator, a real device over USB, or an installable debug APK, never Expo Go.

## Build, run and test (operational)

Prerequisites on the build machine (not needed to edit this repo, needed to
produce an installable app):
- Node.js 20+, npm.
- JDK 17.
- Android SDK + Android Studio (for the emulator and Gradle).

Steps:

```bash
# 1) Build the web member app (sibling checkout) and copy it into ./www
(cd ../adsum-web-membre && npm ci && npm run build)
npm ci
npm run prepare:web

# 2) Generate the native Android project (first time only) and sync
npm run add:android      # npx cap add android
npm run sync             # npx cap sync

# 3a) Run on an emulator or a connected device
npm run run:android      # npx cap run android
#     or open the project in Android Studio:
npm run open:android     # npx cap open android

# 3b) Build an installable debug APK
npm run build:apk        # android/gradlew assembleDebug
#     output: android/app/build/outputs/apk/debug/app-debug.apk
```

Install the APK on a real device with `adb install app-debug.apk` or by opening
the file on the phone.

## Status

  `package.json`, `scripts/prepare-web.mjs`.
- Native `android/` project and installable APK: generated by the steps above on
  a machine with the Android SDK. They are not committed pre-generated.
- Controller (QR scan) shell: planned as a follow-up (needs a camera/barcode
  Capacitor plugin); the member shell is delivered first.

## Conventions

- Branches: work on `feature/*` or `fix/*` from `develop`, then a merge request.
  Merge order `feature/* -> develop -> main`. Never push to `main`.
- Constitution (zero tolerance): no mock data, no file over 500 lines,
  no em-dash (U+2014 / U+2013), no secret in clear. CI enforces these.
- Commit messages in English, Conventional Commits.
